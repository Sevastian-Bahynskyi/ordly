# Adaptive Danish practice specification

Specification for [Ordly issue #11](https://github.com/Sevastian-Bahynskyi/ordly/issues/11), approved interview of 2026-09-24. This document uses the project's glossary and its accepted decisions on practice without runtime AI, Review ownership of retention, and catalog headwords with verified forms.

## Problem Statement

Ordly's Review helps the learner retain saved Danish Material, but it does not offer enough varied practice in meaning, forms, word order, grammar, and contextual use. Existing Practice covers a few activities yet may call AI at runtime, write Review progress, and use a catalog whose meanings are currently Russian only. A separate exercise prototype has ten useful formats, but its visual experience, answer checks, and one-result-per-exercise evidence do not yet fit Ordly. The learner wants flexible practice drawn from their own Material, a much richer reusable Danish content base through B2, and consistent English or Russian support without weakening Review as the trusted memory measure.

## Solution

Keep Review as the default study experience. Offer Practice at any time and an opt-in mixed session through Settings. Practice starts with a 5, 10, 20, or custom minute target, never longer than 30 minutes, and adapts its ten native Ordly exercise formats to the learner's saved Material, selected Danish level, Review history, and internal practice history. An optional short calibration helps when saved history is sparse. Practice records which skills need more work but cannot change Review cards, ratings, due dates, logs, retention measures, or Review counters. In a mixed session, genuine Review tasks retain their normal behavior and precede Practice on the same due word.

The global catalog supplies verified headwords, forms, senses, sentence families, contexts, and prepared answers. Only saved Material becomes a learning target. An unsaved word may appear as translated supporting context; an explicit add action resolves its encountered form through the catalog and saves the headword with all verified forms, including that form. Every Practice exercise is bounded and uses prepared content and deterministic grading. Practice never needs a runtime AI call.

The supplied content and interface use one learner-language preference. English is the default for new profiles, Russian is selectable, and existing preferences and manually written meanings remain intact. Missing locale or exercise content reduces the available Practice formats safely. Completion includes populated, audited content across A1–B2 and measured text and learning coverage, rather than only an empty pipeline.

## User Stories

1. As a learner, I want Review to remain my default study action, so that my existing routine stays familiar.
2. As a learner, I want a Practice action available at any time, so that I can train beyond scheduled reviews when I choose.
3. As a learner, I want to opt into Review + Practice in Settings, so that my default session can include both.
4. As a learner, I want to switch back to Review-only without losing my Material or Review history, so that the combined mode is reversible.
5. As a learner, I want actual Review tasks clearly distinguished from Practice exercises, so that I know which answers affect my memory schedule.
6. As a learner, I want to review a due word before practising that same word in a mixed session, so that Practice does not reveal its answer first.
7. As a learner, I want to choose 5, 10, 20, or custom minutes when Practice starts, so that it fits the time I have.
8. As a learner, I want the custom Practice target capped at 30 minutes, so that starting a session stays a small commitment.
9. As a learner, I want to finish my current answer without a timer cutting it off, so that pacing does not cause a false failure.
10. As a learner, I want to pause and resume the same exercise and answer state, so that leaving the iPhone app does not lose work.
11. As a learner, I want to stop early or start another batch, so that the time target remains flexible.
12. As a learner, I want Practice to start from my Danish level and past learning history, so that I do not have to take a mandatory placement test.
13. As a learner, I want an optional short calibration, so that Ordly can adapt when I know more than my saved history shows.
14. As a learner, I want my saved Material to be the only assessed source in Review and Practice, so that unfamiliar catalog words are not silently assigned to me.
15. As a learner, I want Practice to vary recognition, recall, contextual use, and grammar or forms, so that knowing a translation does not count as knowing every use of a word.
16. As a learner, I want repeated mistakes to change future exercise selection, so that Practice responds to the skills I need to repair.
17. As a learner, I want a choice or revealed answer to carry less weight than a correct unaided answer, so that Practice adaptation reflects what I actually produced.
18. As a learner, I want Practice results kept separate from Review progress, so that an exercise cannot postpone an overdue card.
19. As a learner, I want my Review rings, due count, new-word count, and streak behavior to remain governed by Review, so that their meaning stays consistent.
20. As a learner, I want all ten exercise formats to look and behave like Ordly on my phone, so that Practice feels like part of the app.
21. As a learner, I want clear instructions, feedback, accessible controls, and a responsive bottom navigation in each format, so that exercises remain usable on an installed iPhone PWA.
22. As a learner, I want multiple accepted answers when more than one prepared Danish answer is valid, so that a correct alternative is not called wrong.
23. As a learner, I want word ordering to accept every authored valid sequence, so that changing the opening does not cause a false failure.
24. As a learner, I want a small harmless typo treated differently from the exact form being tested, so that spelling tolerance does not hide a grammar error.
25. As a learner, I want to say “I don't know” without typing a made-up answer, so that uncertainty is represented honestly.
26. As a learner, I want a reveal-and-self-rate exercise labelled as self-reported, so that it is never presented as checked recall.
27. As a learner, I want only the words I missed in a matching or sorting task marked as missed, so that one mistake does not penalise every word.
28. As a learner, I want an ambiguous or unsupported exercise skipped, so that Practice does not teach a doubtful answer.
29. As a learner, I want a shorter session offered when content is sparse, so that Practice remains useful without inventing examples.
30. As a learner, I want Danish sentences from several natural contexts, so that the same word can be practised beyond one memorised example.
31. As a learner, I want English learner-facing text by default on a new account, so that I can use Ordly without first switching away from Russian.
32. As an existing learner, I want my language preference and manually written translations preserved, so that an update does not rewrite my library.
33. As a learner, I want to switch between English and Russian support consistently, so that prompts, hints, feedback, meanings, and examples agree with Settings.
34. As a learner with existing Ukrainian material, I want that material preserved, so that narrowing new supplied content to English and Russian does not destroy it.
35. As a learner, I want tasks requiring a missing translation or hint in my chosen language skipped, so that a different language is not silently substituted.
36. As a learner, I want an unfamiliar word in an exercise to have an accessible translation, so that supporting context does not become a hidden test.
37. As a learner, I want to tap an unfamiliar supporting word and see its senses, so that I can decide whether it belongs in my Material.
38. As a learner, I want to choose Add to Material explicitly, so that merely opening a word does not save it.
39. As a learner, I want a seen inflection such as `gulvet` resolved to the headword `gulv`, so that my library contains the word rather than a stray form.
40. As a learner, I want the saved headword's verified forms to include the form I encountered, so that I can reconnect what I saw with what I study.
41. As a learner, I want ambiguous forms to show candidate headwords and senses, so that the app does not silently choose the wrong lexical word.
42. As a learner, I want a catalog miss to leave me in the normal manual add flow, so that an unavailable reference row does not block capture.
43. As a learner, I want adding another form of an already saved headword to reuse the existing entry or its meaning flow, so that my Review history is not duplicated or reset.
44. As a learner, I want phrases and sentences kept whole when I add them, so that the word-form rule does not collapse expressions.
45. As a learner, I want correctly inflected examples and credible distractors, so that many exercise combinations remain valid Danish.
46. As a learner, I want substantial A1–B2 Material support across everyday situations, grammar, and sentence contexts, so that harder Practice does more than recycle simple word recognition.
47. As a learner, I want optional word audio only where a permitted recording exists, so that an exercise does not imply audio is available for every form or phrase.
48. As a learner, I want the app to resume old Review history after the rollout, so that migration does not make familiar words new again.
49. As a content maintainer, I want every imported fact and generated judgement to retain provenance, so that errors can be traced and corrected.
50. As a content maintainer, I want rejected or uncertain records held out of published Practice, so that scale does not amplify bad Danish.
51. As a content maintainer, I want separate measures of text coverage and learning coverage, so that a high word count is not mistaken for B2 ability.
52. As a content maintainer, I want repeatable audits by language, level, format, and source, so that content quality can be checked after expansion.

## Implementation Decisions

1. **Study modes.** The profile stores a Review-only or Review + Practice default; existing profiles migrate to Review-only. Practice remains a direct action regardless of setting. Mixed sessions have explicit task identity. Due Review for an entry precedes Practice on that entry, while other entries may interleave. A Practice time target does not impose a deadline on due Review or truncate a current answer.
2. **Session contract.** Start Practice with 5, 10, 20, or a custom whole-minute target of 1–30; default the picker to 10 without auto-starting. Persist the seed, exercise queue, duration target, current answer, content revision, and cursor so reloads render the same task. Stop scheduling new exercises near the target and let the current one finish. Pause, finish early, and continue are explicit actions.
3. **Learning boundary.** Learning targets must resolve to owner-scoped saved Material. A catalog row alone cannot receive practice history or Review state. Existing Review new-word limits apply only to Review. Practice may use a small number of translated, unsaved words as supporting context but cannot grade them or implicitly save them.
4. **Review isolation.** Practice actions cannot update Review cards, logs, ratings, due dates, memory rings, status, new-word counts, or the Review-backed streak. Ordinary Review tasks in a mixed session use the existing Review write path and retain Again requeue and rating revision behavior. Enforce isolation at the authenticated server boundary and in the database routine so older clients cannot submit a retired review-change payload. Preserve historical Review rows, including previous-card snapshots, without attempting to identify and delete past practice-originated ratings.
5. **Material isolation.** Practice answer checking, starting, revealing, rating, and adapting cannot append senses, increment shared sense coverage, or fill saved examples. Editing or adding Material is an explicit separate action. Generated content lives in the global content pipeline and never overwrites a learner's saved entry on a background Practice request.
6. **Adaptation.** Read Review history, selected Danish level, and internal skill-specific practice attempts to select learning targets and formats. Track recognition, unaided recall, contextual use, and appropriate grammar/form skills distinctly for selection. Store attempt correctness, assistance, target identity, locale, content version, and response timing if useful; do not expose an independent retention score, practice memory ring, or FSRS schedule. Weigh checked unaided answers above choices and self-rating. Review history is read-only input.
7. **Sparse history.** Start immediately from the selected level and observed Review state. Offer an optional short calibration that uses saved Material and the same bounded grader, with no Review writes. Calibrate exercise selection only; it does not certify a CEFR level.
8. **Ten format integration.** Adapt choice, match, drag-gap, order, type, binary, odd-one-out, category-sort, dialogue, and flash-reveal into Ordly's native navigation, spacing, motion, and feedback. Their content contracts are prepared answer choices, mappings, token sequences, and short bounded responses. Dialogue chooses among authored replies; type handles words, forms, short phrases, and constrained sentences. No format depends on free prose, microphone input, or live model judgement. The format name is not itself an exercise or a learning target.
9. **Grading contract.** Each authored exercise declares its assessed target or targets, the feature being tested, accepted answers or mappings, and optional alternatives. Require deterministic checking with the assessed feature protected from typo tolerance. Order supports multiple authored valid sequences; choice/dialogue accepts all authored valid options. Matching and sorting return per-target evidence. “I don't know,” reveal, hint use, and flash-reveal self-rating are distinct outcomes. An unlisted plausible answer is unverified rather than automatically wrong; the learner can report it for later content review, without changing Material or Review. Never let a client-provided verdict masquerade as independently checked evidence.
10. **Content model.** Separate stable lexical identity (headword and part of speech), sense identity, verified word forms, reusable sentence families, contextual variants, grammar feature, accepted-answer sets, and localized support text. A sentence family has authored transformation slots and constraints rather than a rule that blindly recombines any words. Version content when corrected; stable lexical and sense IDs survive locale additions and ordinary revisions. A correction that changes what was assessed invalidates future tasks built from the old version without rewriting past attempts. Store provenance, quality state, and licence/source metadata for each imported or authored asset.
11. **Headword capture.** Resolve every single-word encountered form against the catalog and reference form data before proposing an addition. Match the candidate's part of speech and sense; where a form maps to several headwords or homographs, present the candidates and require an explicit choice. Save the selected headword as the Danish entry with its selected sense and full set of verified forms, including the encountered form. If the form is not verified for that candidate, do not claim it belongs in the paradigm. Preserve the existing manual fallback and duplicate/extra-meaning confirmation when lookup is absent or uncertain. Do not create another card when the same saved headword/sense already exists. Phrases and sentences use their existing whole-expression flow. The catalog is copied into editable Material; later catalog fixes do not silently rewrite it.
12. **Catalog and form identity.** Extend the form lookup so catalog-backed capture carries forms all the way to the saved entry; a lookup that merely returns the lemma is insufficient. Use COR for normative form facts and grammatical disambiguation, the licensed DDO full-form dataset for broader verified lemma/form coverage, and FLEXIKON only where its older, automatically derived forms pass a stronger verification rule. No source may invent an unsupported form or noun gender. Retain the encountered surface form for display and duplicate detection. Maintain existing per-entry review identities and sense IDs.
13. **Learner language.** Keep one app-wide preference. Set English only for newly created profiles; preserve existing values, including Ukrainian material. Supply English and Russian localizations for interface text, instructions, feedback, hints, example translations, and catalog meanings. Store stable meaning identity separately from localized wording, allowing English and Russian text for the same sense without replacing its ID. Preserve the saved entry's manually entered meaning as authored; add separately identified locale variants only when verified. Never guess that an untagged legacy Russian meaning is English. Tasks requiring a missing locale variant are ineligible; offer Danish-only tasks when their answer contract supports them. Language switching must not recreate Review cards or invalidate sense-based history merely because display text changed.
14. **Prepared content at scale.** Expand the global catalog beyond its present Russian-only meanings with English counterparts, phrases, sentence families, contexts, accepted variants, grammar features, and safe distractor relationships. Build reference facts deterministically from licensed resources. Use offline or batch semantic generation only for content that needs it, followed by validation and human audit; no runtime generation is part of Practice. Maintain resumable, versioned imports with idempotent keys, quarantine failed rows, and synchronise only validated snapshots. Do not copy DDO website examples or audio into a new corpus without checking the rights for those assets separately from DSL's open lexical lists.
15. **Coverage definition.** The named lexical benchmark is DSL's `freq-30k-ex` lemma list, whose published frequencies aggregate inflected forms over its underlying corpus. Compute weighted lemma coverage as the sum of frequencies for eligible supported catalog lemmas divided by the sum for all eligible lemmas in that list; report the excluded classes and the fact that this is coverage **within that list**, not of all Danish text. Target roughly 90% while separately reporting coverage by frequency band and open/closed word class so function words cannot hide lexical gaps. Freeze a separate, rights-cleared assessment set of unseen Danish sentences before tuning the corpus, and report token, lemma, and phrase coverage there as an independent check. A1–B2 learning coverage uses a published matrix of everyday situations, meanings, forms, and communicative/grammar functions aligned to the Council of Europe's descriptors. Every selected matrix cell needs usable, audited exercises in both learner languages. Neither metric certifies a learner as B2.
16. **Content quality gates.** Require every published asset to pass structural, language/script, sense/form identity, accepted-answer, ambiguity, inflection-in-context, provenance, and duplicate checks. Run seeded human audits stratified by learner language, level, format, source, sentence family, and low-confidence facts. Pilot on a small set before population; stop and repair a batch whose audited accuracy is below 95% in any measured stratum or that has an unresolved severe teaching error. Publish rates with denominators and uncertainty, not a per-row certificate. Track actual distinct valid task combinations after constraints and deduplication; do not claim billions from raw Cartesian products.
17. **Missing content.** A saved word with no suitable sentence or localized meaning remains eligible for formats that can be graded safely. The planner skips unsupported formats without inventing content. If a requested duration cannot be filled, show how much usable Practice is available, offer the shorter session, and leave ordinary Review accessible. A content correction or outage must not prevent manual Material capture or Review.
18. **Security and migration.** Owner scope every practice history and saved Material operation. Keep global catalog read-only to signed-in learners; keep generation credentials server-side. Do not log typed answers, personal sentences, or full provider payloads. Guard the Practice commit routine and any shared coverage helpers against retired cross-mode writes; validate versioned persisted sessions and safely retire old AI-enabled sessions. Preserve review logs, card state, saved sense IDs, and the first-account access rule. Apply schema changes through ordered migrations, then import large reference data through resumable scripts. Check exact production schema and RLS immediately before implementation.
19. **Delivery.** Release only after the native ten-format experience, mode controls, strict Review boundary, English/Russian supplied content, headword capture, validated content pipeline, and substantial populated A1–B2 coverage work together. Preserve responsive navigation and network-first PWA updates. The next `/to-tickets` step creates no more than five broad implementation issues from this specification.

## Testing Decisions

1. **Primary seam:** test authenticated learner journeys across the public session and Material-add boundaries: start/resume/answer/finish Practice, run mixed Review, switch language, and add an encountered form. Assert visible outcomes and persisted Review/Material state rather than private planner steps. This is the highest useful shared seam for the product behavior; content import has its own offline validation gate. The prior interview already approved the user-visible behavior and capped questions at 20, so this specification does not reopen a seam interview.
2. Test that Practice never changes Review cards, due dates, logs, learning status, memory rings, new-word counts, or Review-backed streaks, including when a legacy client submits a review-change payload. Test the database permission/RPC boundary as well as the current client path.
3. Test mixed sessions with a due word: Review comes before Practice for that word; Again requeues in the active Review session, and Good ↔ Again revisions preserve the original prior card state. Practice-only attempts never satisfy the due card.
4. Test pause/resume on an installed iPhone PWA and a narrow browser view: answer text, choices, seed, time target, and cursor survive; no timer disables an input. Exercise controls remain accessible by touch and keyboard, and localized text does not overflow.
5. Test all ten formats through their user actions. Cover multiple valid dialogue replies and word orders, a harmless typo beside a targeted wrong form, “I don't know,” reveal/self-rating, and one error among several matches. Verify each assessed word receives only its own outcome.
6. Test sparse content, missing locale, stale content version, empty catalog, and network interruption. Unsupported formats are skipped and the learner sees a shorter-session option; Review and manual capture still work.
7. Test language switches from an existing Russian profile with manually saved meanings, a new English profile, and retained Ukrainian material. Catalog-backed English/Russian meanings map to the same sense identity and preserve Review history; missing variants never appear under the wrong language label.
8. Test adding `gulvet` as `gulv` with all verified forms, adding the headword directly, adding a different form of an existing word, an ambiguous homograph, a catalog miss, and a multiword phrase. Verify no duplicate card, guessed lemma, guessed form, or reset history.
9. Test the offline content gate with corrupt forms, missing accepted variants, mistranslated support text, ambiguous options, mismatched grammatical annotations, licensing metadata gaps, and unsafe sentence recombinations. Exercise constructors may use only validated assets. Re-run the same import to verify stable identities and no duplicated rows.
10. Prior art is the repository's existing practice planner/session tests, Review rating revision tests, catalog lookup/form tests, and owner-scoped SQL tests. Extend these where they observe the new user contract. Run the full TypeScript check, focused tests, production build, and iPhone-sized manual journeys. For implementation commits, verify GitHub Build and Vercel status for the exact SHA before claiming deployment success.

## Out of Scope

- Removing AI from the rest of Ordly; the user intends that later. Runtime AI is prohibited throughout Practice.
- Automatically assigning unsaved catalog entries as Practice or Review learning targets.
- Unrestricted prose, live conversation, microphone/speaking assessment, or a listening exercise format.
- A new independent practice mastery or retention score, memory ring, or FSRS schedule.
- Automatic merging of existing Material entries or deletion/recalculation of historical Review logs.
- Expanding supplied learner-language content to Ukrainian, while preserving existing Ukrainian preferences and material.
- A guarantee of offline operation; the current PWA update and network behavior must continue working.
- A claim that generated variants number in the billions, or that catalog coverage proves CEFR B2 proficiency.
- Implementation issues beyond the five-ticket maximum required by issue #11.

## Further Notes

- The live production inventory checked on 2026-09-24 contains 2,939 global catalog entries and 3,932 catalog senses, all tagged Russian. It also has owner-scoped Practice state and attempts, saved word forms, and the deployed Practice commit routine. These counts are a baseline, not proof of full A1–B2 coverage.
- The current catalog schema keys a sense independently of language in a way that prevents simply inserting an English row with the same sense ID. The locale migration must preserve existing IDs and Review history while allowing parallel localized text.
- The current Practice implementation can write Review state, shared sense coverage, streaks, and saved examples. Isolation requires an explicit migration and old-session handling, not just a new screen.
- DSL's [open resource terms](https://korpus.dsl.dk/resources/licences/dsl-open.html) allow broad use of the listed frequency, DDO lexical, and FLEXIKON resources but exclude publishing a competing dictionary and request attribution. The [frequency list description](https://korpus.dsl.dk/resources/details/freq-lemmas.html) explains its lemma weights; the [DDO full-form description](https://korpus.dsl.dk/resources/details/ddo-fullforms.html) distinguishes homographs; [FLEXIKON's description](https://korpus.dsl.dk/resources/details/flexikon.html) warns its automatically derived forms are not norm-checked. The [COR publisher](https://ordregister.dk/) marks its index CC0. [DDO's citation page](https://ordnet.dk/ddo/om-ordbogen/citering/) states that website material is copyright-protected, so lexical-list permission must not be assumed to cover example sentences or audio.
- The [Council of Europe's CEFR companion volume](https://www.coe.int/en/web/common-european-framework-reference-languages/cefr-companion-volume-and-its-language-versions) supplies the A1–B2 descriptors for the learning-coverage matrix. These descriptors describe language abilities, not a lexical count.
- Source and licence checks are as of 2026-09-24. The content pipeline records source version and terms at each import; any new source requires its own verification before content is published.
